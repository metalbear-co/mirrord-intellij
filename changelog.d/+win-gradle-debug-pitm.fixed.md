Fix Windows-native Gradle **Debug** sessions running without the mirrord layer (previously "Timed out waiting for layer to signal injection complete", or breaking the build with "Unable to start the daemon process"). IntelliJ debugs the Gradle *daemon* — not the forked application JVM — so the earlier attach flow kept targeting the daemon. Debug now uses the same `mirrord pitm` init-script path as Run: it relaunches the forked JavaExec JVM under pitm while passing IntelliJ's dispatched `-agentlib:jdwp` argument through untouched, so the layer loads into the app JVM and the debugger still attaches to it. The init script also detects the JDWP port and sets `MIRRORD_IGNORE_DEBUGGER_PORTS` for the child, so the layer leaves the debugger's loopback connection alone instead of tunnelling it to the target (which otherwise reset the JDWP handshake with "TRANSPORT_INIT(510)").
